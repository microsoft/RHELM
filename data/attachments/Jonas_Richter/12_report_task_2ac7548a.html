2. Overview of New UI Features

2.1 Usability and Accessibility Enhancements

The latest release places a strong emphasis on user experience, security, and accessibility for a broad audience.

  • Unified Dashboard: The redesigned dashboard centralizes access to encryption key management, session controls, and audit logs. Navigating key features is now more intuitive thanks to a streamlined sidebar, context-sensitive help pop-ups, and support for keyboard shortcuts.
  • Accessibility Improvements: The interface now fully complies with WCAG 2.1 AA guidelines. Users with visual impairments can take advantage of improved screen reader compatibility, adjustable text sizes, and multiple color contrast options to tailor the UI to their needs.
  • Data Export Wizard: Exporting data has become significantly easier through a step-by-step wizard. Users choose the data format (JSON, CSV, or encrypted archive), follow guided prompts, and are provided with progress status and completion confirmations. Each export action requires GDPR-compliant consent, and clear explanations are provided at every step.
  • Multi-Factor Authentication (MFA) Panel: The MFA onboarding flow now guides users through email, TOTP, or hardware token setup in clear, incremental steps. It prominently alerts users if they haven't generated backup codes, ensuring account safety. All MFA data is processed with explicit consent and can be deleted upon request, reinforcing privacy by design.
  • Real-Time Consent Manager: Users can now review, revoke, or update all data processing consents within a single, comprehensive module. Every change made is automatically logged for auditing, strengthening transparency.
  • Localization Switcher: The language selector now automatically detects browser preferences and supports 12 EU languages, making the platform accessible to a wider European audience.

2.2 Policy and GDPR/Privacy Measures

Data protection and regulatory compliance remain foundational to the project’s development philosophy.

  • Explicit Consent Mechanisms: Every sensitive action—such as exporting data, sharing information, or connecting to an SSO provider—triggers a standardized GDPR-consent prompt, with supporting information available via “learn more” links. These measures fully comply with Article 7 (Conditions for Consent) of the GDPR [2].
  • Data Minimization by Default: Whenever optional data fields appear, they are clearly marked as "not required," and the UI collects only essential data for core functions.
  • Data Portability: Users can download all personal data and associated metadata at any time, directly from the interface, supporting GDPR Articles 15 and 20.
  • Right to Erasure/Anonymization: The platform makes it straightforward for users to request erasure or anonymization. As soon as a request is submitted in the UI, the workflow is triggered instantly, with notification provided once the process is complete and all actions fully logged for records.

Transitions and integration of these features are designed to ensure the platform remains aligned with current privacy regulations and user expectations for transparency.

3. Addressing Dr. Katarzyna Nowak’s Inquiry – Structured Q&A

Background

Dr. Katarzyna Nowak reached out via the project’s GitHub Issues to request clarification on the implementation of audit logging and its potential implications for user privacy, especially in the context of European university research scenarios.

Q&A Summary

Question Answer Related Docs/Discussions Authoritative References
What user information is recorded in audit logs under the new system? The audit logs store minimal metadata: a hashed user ID, timestamp, and a summary of the associated action. No content in plaintext is logged, and all IP addresses are anonymized by default. Audit Logging Spec GDPR Art. 5(1)(c)
Can audit logs be exported, and if so, who can access them? Audit log export is limited strictly to users granted "Audit Export" privileges. All export actions are themselves logged, and the exported file is encrypted and requires secondary authentication for access. GitHub #342 EUC Guidelines
Are automated logs considered personal data under GDPR? Yes; since the metadata remains potentially reversible (even when anonymized), it is treated as personal data. The platform requires explicit user disclosure and consent at onboarding, in line with GDPR recommendations. Privacy Policy EDPB Opinion 4/2007
How does the project support GDPR Art. 15 data access and correction rights for log metadata? Users have direct access to their log metadata at any time from their accounts. The “Data Requests” UI module allows them to request corrections or deletion, and all actions are tracked through the same interface. User Data Rights UI GDPR Art. 15-18
What is the process for erasing or anonymizing log entries at user request? Users can initiate the erasure or anonymization process from their account settings. The system removes personal identifiers from logs within 24 hours and sends an automatic compliance notification to the user when the process is completed. Anonymization Workflow CNIL FAQ

This approach provides researchers and institutional users with the clarity and reassurance necessary for academic environments that prioritize privacy and rigorous compliance.

4. Usage Instructions

For End-Users

Setting Up Your Account - Register through the main portal, where the GDPR-compliant privacy policy is presented in full. - MFA activation is recommended at registration. Step-by-step instructions make it easy to enable via email, TOTP, or hardware token. - The user can select their preferred language during onboarding for a localized experience.

Encrypting Data - Go to the “Data Vault” tab and select files or data to encrypt. - The default encryption algorithm is AES-256-GCM, ensuring robust protection. - Before saving, users can set sharing permissions and specify optional access expiration dates for each encrypted item.

Exporting Data with Consent - Under “Settings > Export Data,” users find an export wizard guiding them through data category selection (e.g., profile, audit logs, settings). - A clear consent dialog provides detail about what will be exported and why. Users confirm to proceed, after which their data is packaged and made available in their chosen format.

Requesting Data Access, Correction, or Deletion - The “My Rights” section of account settings allows users to make formal requests: access data, request corrections, or invoke the “right to erasure.” - Once a request is confirmed, a progress tracker appears, and the user receives updated status notifications. Finalized actions generate downloadable confirmations for the user’s own records.

For Technical Stakeholders

Connecting External Identity Providers - SSO and MFA integrations are managed from "Admin > Integrations." The configuration wizard covers SAML, OAuth2, and OpenID Connect flows in detail, with mandatory HTTPS for all endpoints. - Recommended practice includes testing authentication and logging flows with non-production accounts before enabling for all users.

Audit Log Maintenance - Audit logs are managed via the “Logs” menu. Export or advanced management privileges should be granted only to vetted users, with keys rotated regularly. - The built-in anonymization tool enables periodic identifier purging, supporting ongoing compliance and minimizing unnecessary data retention.

Best Practices and Security - Deploy only the latest stable, GDPR-vetted release. - Separate administrative rights from standard user privileges. - Schedule regular accessibility and compliance audits, referencing both WCAG 2.1 and EN 301 549 standards. - All updates to policy or practice are documented in changelogs and communicated through user notices and community forums as required. - EU-based hosting and infrastructure are mandatory for data residency. - Technical workflow: User actions in the UI launch backend processes, each event triggers an audit entry (with hashed user ID, timestamp, and action summary), the system checks for valid user consent before proceeding, and either allows or denies actions accordingly.
