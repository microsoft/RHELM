# Zigbee Sensor Integration Issue on Raspberry Pi 4  
**Date:** 2024-08-31  
**Author:** Martin Keller, Embedded Systems Software Developer, Stuttgart, Germany

---

## Executive Summary

This report details the process of diagnosing and resolving a Zigbee sensor integration issue with an Aqara Temperature & Humidity Sensor connected to a Raspberry Pi 4 Model B. The system leveraged a ConBee II Zigbee USB radio, Zigbee2MQTT as the Zigbee stack, and Home Assistant for smart home integration. The sensor sporadically became unavailable and failed to report measurements consistently. Through thorough hardware and software checks, consulting documentation, and engaging with community discussions, the primary issue was traced to radio interference from the Raspberry Pi’s USB 3.0 ports. Relocating the ConBee II dongle to a USB 2.0 port and adding a short cable extender resolved the problem, resulting in steady sensor updates within Home Assistant. This experience highlights the importance of diligent USB port selection, clear configuration documentation, and community knowledge sharing for robust Zigbee deployments on embedded devices.

---

## Problem Description

**Hardware and Software Overview:**

- **Raspberry Pi 4 Model B** (Revision 1.4, 4GB RAM)
- **ConBee II USB Dongle** (Firmware: 0x26780700, released May 2024 [1])
    - *Note:* CC2531 coordinator (alternative, not used) [2]
- **Sensor:** Aqara Temperature & Humidity Sensor (Model: WSDCGQ11LM, Firmware 35_20240120 [3])
- **Software Stack:**
    - Zigbee2MQTT v1.38.0 (August 2024) [4]
    - Home Assistant v2024.8.2 [5]
    - Node.js v18.20.3
    - Mosquitto MQTT Broker v2.0.18
- **Power:** Official Raspberry Pi 4 adapter (5V, 3A)

**Symptoms Encountered:**

- The sensor was frequently labeled “Unavailable” in Home Assistant.
- Temperature and humidity readings were delayed or altogether missing, despite visible sensor activity.
- Zigbee2MQTT logs repeatedly stated `Failed to ping device` and `Interview failed`.
- Home Assistant logs noted missing MQTT events.

What began as an intermittent sensor connection quickly revealed deeper underlying problems in the Zigbee communication layer.

## Troubleshooting Approach

To identify and resolve the issue, I followed a structured troubleshooting process, as outlined below:

| Step | Actions Taken | Findings | Outcome |
|------|--------------|----------|---------|
| 1 | Checked power and USB connections, shifted dongle to USB 2.0 port | ConBee II detected via `lsusb`; voltage drop noted on USB 3.0 | No improvement; instability persisted |
| 2 | Verified firmware versions | Zigbee2MQTT logs confirmed both radio and sensor up-to-date | Versions compatible; no update required |
| 3 | Updated Zigbee2MQTT and Home Assistant | Restarted services and checked update logs | Running on latest releases; problem remained |
| 4 | Reviewed Zigbee2MQTT logs | Repeated `[info] Interview failed for device '0x00158d0001a2b3c4'` errors | USB/RF interference suspected |
| 5 | Experimented with USB ports and used a short cable extension | Moved dongle to USB 2.0, added 30cm shielded cable | Connectivity and update rates improved noticeably |
| 6 | Enabled debug logging in Zigbee2MQTT | Detailed logs over 2-hour observation | USB 3.0 showed orphaned packets; USB 2.0 logs indicated successful communication |
| 7 | Examined Zigbee network map | Exported network topology from MQTT topic | Sensor often dropped in link quality (LQI <30), confirming instability |
| 8 | Re-paired the sensor | Reset and re-interviewed via Zigbee2MQTT | Pairing successful, updates resumed |
| 9 | Checked adapter firmware update | Used ConBee II official flashing tool | Latest firmware installed; no changes needed |
| 10 | Consulted community forums | Found reports of USB 3.0 interference with Zigbee radios | Recommendation to use USB 2.0 ports reinforced |

Each step built on the previous findings until the issue was fully diagnosed.

## Root Cause Analysis

Investigation revealed the primary culprit as electromagnetic interference generated by USB 3.0 ports on the Raspberry Pi 4. Zigbee radios operate in the 2.4GHz band, and USB 3.0 ports are widely documented to emit noise disrupting wireless signals at this frequency [1]. Debug-level protocol traces confirmed packet loss and corrupt messages when the ConBee II dongle was plugged into a blue-colored USB 3.0 port. Connectivity improved dramatically when switched to the black USB 2.0 port with a short extension cable, physically distancing the dongle from the Pi’s mainboard and mitigating interference.

Link quality dips in the network map, frequent failures during Zigbee device pairing (interview failures), and persistent “Unavailable” status in Home Assistant solidified USB 3.0 interference as the root cause. Firmware and software were consistently verified as current, confirming that outdated versions were not contributing to the issue.

---

## Solution Implementation

Drawing on both manufacturer documentation and community troubleshooting advice, I implemented a multi-part solution:

1. **Relocated the ConBee II dongle to a USB 2.0 port**—the black port on the Pi, known for lower noise emissions.
2. **Used a short, shielded 30cm USB extension cable** to further reduce RF coupling between the dongle and the Pi’s board.
3. **Repaired the Zigbee network** by resetting and re-pairing the Aqara sensor, allowing Zigbee2MQTT to successfully interview and integrate the device.
4. **Updated configuration documentation** in Zigbee2MQTT, confirming serial port and adapter settings as below:
   ```yaml
   serial:
     port: /dev/ttyACM0
     adapter: deconz
   advanced:
     log_level: info
   ```
5. **Verified system stability**—sensor readings now appear in Home Assistant and Zigbee2MQTT frontends at one-minute intervals, with “Available” status.

## Lessons Learned

- **USB Port Selection is Crucial:** Always connect Zigbee radios to USB 2.0 ports on the Raspberry Pi to avoid 2.4GHz interference seen on USB 3.0 ports. This advice is supported by official sources and widely shared community experiences [1][4][8].
- **Physical Placement Matters:** Use a short, shielded USB extension cable to keep the radio antenna away from noise sources and improve reliability.
- **Keep Firmware Current:** Ensuring up-to-date radio coordinator and sensor firmware prevents compatibility issues and supports stable operation [1][3][4].
- **Document Configuration:** Record all hardware, software, and Zigbee settings for reproducible deployments and easier future maintenance.
- **Leverage Community Knowledge:** User forums and community threads often contain practical, real-world solutions not found in manuals, making them an essential resource for troubleshooting.
- **Monitor System Health:** Take advantage of debug logs and network mapping tools for identifying connectivity issues and optimizing Zigbee network topology.
- **Maintain Thorough Troubleshooting Records:** Clear documentation of the diagnosis and resolution process, supported by screenshots and technical details, streamlines future engineering tasks and can benefit others facing similar challenges.
